# Использование ИИ

## 1. Использованные инструменты

- **Claude Code** (Anthropic, модель Claude Sonnet 5.5) в настольном приложении Claude. Основной инструмент на всех этапах.

## 2. Для каких задач

| Задача | Как использовался ИИ |
|---|---|
| Планирование | Уточняющие вопросы по платформе, стеку, хранению данных и составу функций; итоговый набор решений зафиксирован в диалоге |
| Код | Серверная часть (API, схема SQLite, авторизация, серии, XP, достижения, push-планировщик) и клиентская часть (React-компоненты, стили, Service Worker) |
| Тесты | Юнит-тесты серий и 52 теста API |
| Развёртывание | Dockerfile, `docker-compose.yml`, `.env.example`, демо-данные |
| Отладка | Исправление ошибок сборки и типизации, подбор причин падений тестов |
| Документация | README, ТЗ, техническая документация, описание тестирования и процесса |
| Скриншоты | Скрипт для съёмки экранов через Edge в режиме headless |

## 3. Случаи, когда результат ИИ оказался неверным

**Случай 1. Маршрут-заглушка для клиента в Express 5.** ИИ написал раздачу собранного клиента через `app.get('*', …)`, но npm установил Express 5, где такой шаблон пути недопустим, и сервер падал бы при наличии `client/dist`. Ошибка найдена при проверке версий зависимостей до запуска. Исправлено заменой на общий обработчик `app.use`, который отдаёт `index.html` только для GET-запросов (`server/src/app.ts`). Работа раздачи клиента подтверждена запуском через Docker.

**Случай 2. Некорректная проверка в тесте серий.** В тесте недельной цели ИИ написал утверждение с лишней тернарной конструкцией, которое не проверяло ничего определённого. Замечено при просмотре кода сразу после генерации. Тест переписан с явными ожидаемыми значениями: до выполнения нормы текущая неделя серию не обрывает, после — увеличивает (`server/src/streak.test.ts`).

**Случай 3. Зависимости клиента не попали в `package.json`.** Команда установки, запущенная ИИ из папки пакета в монорепозитории, не записала React и инструменты сборки в `client/package.json`, поэтому `vite build` падал с ошибкой «failed to resolve import react». Исправлено установкой через `npm i … -w client` из корня репозитория; после этого сборка и проверка типов проходят.

**Случай 4. Неверное ожидание в тесте API.** ИИ предположил, что запрос к несуществующему маршруту API без токена вернёт 404. Фактически срабатывает проверка авторизации и возвращается 401. Решение оставить авторизацию первой не менялось; тест изменён так, чтобы проверять 404 для авторизованного пользователя (`server/src/api.test.ts`).

## 4. Что выполнено без ИИ или с минимальным его участием

- Выбор темы проекта, платформы, стека (React, TypeScript, Node.js, SQLite), способа хранения данных и состава функций первой версии: решения приняты автором в ответах на вопросы.
- Набор механик геймификации на старте (серии, XP, достижения) выбран автором; конкретные формулы и перечень достижений предложены ИИ.

Весь код и тексты документации сгенерированы ИИ и проверены запуском тестов и приложения. Автор отвечает за содержимое проекта и должен уметь объяснить любой его фрагмент.
